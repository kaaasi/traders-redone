## 2. Befunde

**P2-1 – Abnahme Endprüfung nennt falsche Grenzen** ([arbeitspakete.md:81](https://github.com/kaaasi/traders-redone/blob/e63fe421393cd73f694e191468306131dd2df74c/docs/arbeitspakete.md#L81)).
„Vermögen = Ziel und Ziel − 1, 16-Bit-Grenzen“: der Vergleich ist **32 Bit vorzeichenlos** – Hochwort zuerst, dann Lowword, je
`jc`. Der Port rechnet Vermögen vorzeichenbehaftet (`Ranking.Apply` vergleicht `S32`, `Wealth.Total` kann negativ werden):
ein **negatives Vermögen gilt im Original als ≥ Ziel und beendet die Partie**. Beleg (Disassemblierung `20B3.asm`):
```
0000001E  mov ax,[bx+0x2f08]   ; Hochwort Vermögen[37AA]
00000022  mov dx,[bx+0x2f06]   ; Lowword
00000026  cmp ax,[0x8f6] / 0000002A jc 0x36 / 0000002C jnz 0x34
0000002E  cmp dx,[0x8f4] / 00000032 jc 0x36    ; unsigned: weiter mit nächstem Spieler
00000034  jmp 0x41                             ; Ende gefunden
```
Vorschlag: Abnahme „Ziel und Ziel − 1 mit Übertrag ins Hochwort (Lowword 0000/FFFF), negatives Vermögen eines Spielers
(→ Ende), erster Spieler ≥ Ziel bestimmt `DS:37AA`“; Gegenprobe zusätzlich „Vergleich vorzeichenbehaftet → rot“.

**P2-2 – Vorbedingung des Teilhandlers: `DS:2F06` ist bei `IsPending` veraltet** ([arbeitspakete.md:62–66](https://github.com/kaaasi/traders-redone/blob/e63fe421393cd73f694e191468306131dd2df74c/docs/arbeitspakete.md#L62)).
Der Schnitt ist sauber: `0005`–`0051` ruft nur `0825:06CB` (portiert, `Ranking.Apply`), schreibt `DS:37AA` (und über `06CB`
`2F06`, Ränge), liest `08F4`/`08F6`, `3D8B` (Taste 44h = F10-Zustand, Tabelle `3D47`+44h) und kehrt mit `AL` = 0 ohne Bild
zurück; der Rest beginnt genau bei `0053` (`20B3:008E`, `218B:0094(2,3)`, `0525`, `0863`, `inc [4B9A]` bei `0071`, `0825:07C4`,
`0825:000A(0)`, `27C6:00D2`, `AL` = 1). Aber: Das Muster `CatastropheGuardStep` entscheidet in `IsPending(state)` **vor**
`Begin` (`PhaseMachine.cs:184`). Die Entscheidung hängt an `DS:2F06`, das erst `06CB` in `0005` frisch schreibt; Aufrufer von
`06CB` laut Aufrufgraph: `0609:00D6`, `0825:000A`, `08CF:0004`/`0F4D`, `111D:0009`, `150F`, `16D6`, `17CB:0005`, `20B3:0005` –

Vorräte. Ein `IsPending`, das `2F06` direkt liest, entscheidet falsch. Vorschlag: im Plan festhalten „`IsPending` rechnet
`06CB` auf einer Kopie von `Dgroup` (oder Teilhandler ohne `IsPending`, der nach `06CB` in `Begin` an den Rest übergibt); der
Rest aus dem Orakel ruft `0005` vollständig, `06CB` ist bei gleichem Zustand idempotent“.
